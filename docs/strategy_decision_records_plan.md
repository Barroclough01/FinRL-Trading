# Strategy Decision Records Design and Implementation Plan

Last updated: 2026-06-12
Status: **IMPLEMENTED IN THE CURRENT WORKFLOW (2026-06-12)**

This document records the implemented strategy decision-record flow for Task 1 in the Near-Term Paper Comparison Foundation. The weekly paper-trading run now persists records to SQLite and `logs/strategy_decisions.jsonl` for every account/date.

## Requirements

For every account and run date, we must record:

- **Run Metadata**: Run date, account name, strategy/config path, config hash
- **Strategy State**: Regime state, active groups, ranked groups and group metrics, fallback status, and fallback reason
- **Weights & Sizing**: Target weights
- **Positions & Account State**: Pre-trade positions, post-trade positions, cash, equity, and benchmark snapshot
- **Execution Details**: Order plan, submitted orders, and filled orders

## Architecture

We will use a dual-storage model to maximize durability and ease of analysis:

1. **SQLite Table (`strategy_decisions`)**: Perfect for SQL queries, reporting dashboards, and weekly performance audits.
2. **JSONL Mirror (`logs/strategy_decisions.jsonl`)**: Append-only file, easy for LLM/agent inspection, debugging, and backup.

### 1. SQLite Schema

We will add a new table `strategy_decisions` to `data/finrl_trading.db`:

```sql
CREATE TABLE IF NOT EXISTS strategy_decisions (
    id                     INTEGER PRIMARY KEY AUTOINCREMENT,
    run_date               TEXT NOT NULL,
    account_name           TEXT NOT NULL,
    config_path            TEXT,
    config_hash            TEXT,
    regime_state           TEXT,
    active_groups          TEXT, -- JSON array
    ranked_groups          TEXT, -- JSON array
    fallback_status        INTEGER DEFAULT 0, -- 0/1 boolean
    fallback_reason        TEXT,
    target_weights         TEXT, -- JSON object {symbol: weight}
    pre_trade_positions    TEXT, -- JSON array of positions
    order_plan             TEXT, -- JSON object (sells/buys plan)
    submitted_orders       TEXT, -- JSON array of submitted orders
    filled_orders          TEXT, -- JSON array of filled orders
    post_trade_positions   TEXT, -- JSON array of post-trade positions
    cash                   REAL,
    equity                 REAL,
    benchmark_snapshot     TEXT, -- JSON object {spy_close: x, qqq_close: y}
    created_at             TEXT DEFAULT (datetime('now')),
    UNIQUE(run_date, account_name)
);
```

### 2. JSONL Mirror Structure

Every line in `logs/strategy_decisions.jsonl` will be a standalone, self-contained JSON object containing all the fields listed above. This file will be append-only.

## Implementation Path

We will integrate this directly into the weekly paper-trading pipeline in `run_paper_trading.py`:

1. **Schema Initialization**: Update `init_db` in `track_metrics.py` (or initialize it directly in `run_paper_trading.py`) to create the `strategy_decisions` table.
2. **Data Collection during `run_account`**:
   - Collect pre-trade positions and cash/equity from Alpaca before rebalancing.
   - Run the strategy to get target weights, and extract fallback status, fallback reason, regime state, and active/ranked groups from the strategy output.
   - Capture the dry-run order plan generated by the executor.
   - Submit orders and record the submitted orders list.
   - After order submission, fetch the post-trade positions and final cash/equity.
   - Query the benchmark prices for the benchmark snapshot.
3. **Database & File Writing**:
   - Write the compiled record to the SQLite database.
   - Append the compiled record as a single line in `logs/strategy_decisions.jsonl`.
